01 · Contesto

Dalla specifica SCAS al verdetto

Le SCAS descrivono il comportamento atteso, ma la logica che decide PASS/FAIL viene spesso implementata caso per caso nel codice.

Approccio ad hoc
Test A → verifier A
Test B → verifier B
Test C → verifier C

Logica dispersa, poco riusabile, difficile da ispezionare fuori dal codice.

→
Obiettivo della tesi
SCAS→DSL→Engine→Verdict

Separare la logica del test dall’implementazione che la esegue.

06 · Linguaggio

DSL — selezionare l’evidenza e definire il criterio

La DSL descrive sia quali eventi estrarre dal traffico sia quali proprietà verificare su quegli eventi.

1 · Evidence selection

07 · Linguaggio

Grammar & parsing

La grammatica definisce formalmente i costrutti ammessi dalla DSL e il parser li trasforma in una rappresentazione strutturata.

sequence_rule: "SEQUENCE" "{" sequence_element+ "}"
collect_rule:  "COLLECT" FIELD "AS" NAME
unique_rule:   "REQUIRE" "UNIQUE" FIELD
temporal_rule: "MFOTL" "CASE" VALUE MFOTL_BLOCK

INPUT file .dsl → OUTPUT rappresentazione strutturata della regola
